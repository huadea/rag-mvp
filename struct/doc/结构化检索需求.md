# 结构化检索需求

## 1. 模块目标

结构化检索用于查询招标文件中的固定关键信息。

它的目标是：

```text
用户提出确定性问题 → 系统识别字段 → 返回字段值和来源依据
```

适合查询：项目编号、项目名称、招标人、最高限价、投标截止时间、是否接受联合体等信息。

---

## 2. 核心需求

系统需要将招标文件中的关键信息维护为结构化字段。

每个字段至少包含：

```text
字段名
字段值
字段分组
来源章节
来源原文
置信度
是否人工确认
```

结构化检索不是直接查全文，而是从已维护的字段中读取答案。

---

## 3. 第一阶段字段范围

### 项目基本信息

```text
项目编号
项目名称
招标方式
招标人
采购单位
采购内容
```

### 标包与预算信息

```text
标包数量
标包号
标包名称
标包最高限价
最高限价合计
```

### 时间与地点信息

```text
招标文件获取时间
投标截止时间
开标时间
开标地点
保证金到账截止时间
```

### 投标资格信息

```text
是否接受联合体
独立法人要求
信用要求
平台注册要求
其他资格要求
```

### 递交与联系方式

```text
递交方式
电子文件要求
签字盖章要求
投标保证金要求
招标人联系方式
采购单位联系方式
```

---

## 4. 支持的查询问题

系统需要支持用户用自然语言查询字段信息，例如：

```text
这个项目的基本信息是什么？
项目编号是多少？
招标人是谁？
采购单位是谁？
最高限价是多少？
有哪些标包？
投标截止时间是什么？
在哪里开标？
是否接受联合体投标？
投标保证金要求是什么？
联系方式是什么？
投标人资格要求有哪些？
```

---

## 5. 查询结果要求

查询结果应包含：

```text
直接答案
字段明细
来源章节
来源原文
置信度
```

示例：

```text
项目编号：CF25ZFF0142

来源章节：第一章 招标公告 / 一、项目基本情况
来源原文：（一）项目编号：CF25ZFF0142
置信度：高
```

---

## 6. 边界说明

结构化检索只负责确定性字段查询。

不负责：

```text
技术方案生成
方案目录生成
复杂需求总结
评分点分析
投标方案撰写
```

这些能力应由向量检索和大模型处理。

---

## 7. 一句话总结

结构化检索的需求是：

```text
把招标文件中的关键字段维护成结构化信息，用户提问时从字段库中读取准确答案，并提供来源依据。
```
